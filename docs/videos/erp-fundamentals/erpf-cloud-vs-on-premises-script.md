# Video script: Cloud vs On-Premises ERP

ERP Fundamentals lesson video (/videos/erpf-cloud-vs-on-premises.mp4), shown at the top of the lesson. Built from the lesson content; Odoo colours, nexusEPM logo, narration by Microsoft neural voice Neerja (Indian English) with captions.

| # | On screen | Narration |
|---|---|---|
| 1 | Title card: **Cloud vs On-Premises ERP**. Where the ERP runs changes cost, control, customization, upgrades and responsibility. | Welcome to lesson six. In this video you will learn the main ERP deployment models, how to choose between them, and the one responsibility that always stays with the client, wherever the ERP runs. |
| 2 | **Same question, different deployment**. Cards: Harbor Steelworks · Lumen Consulting Group | Meet two fictional clients. Harbor Steelworks is a fabrication workshop in an industrial zone with unreliable internet. Lumen Consulting Group is a twenty five person advisory firm whose staff work from client sites and from home. Both are choosing an ERP, and the right deployment model for each is different. That choice affects cost, control, customization, upgrades and who is responsible for security. |
| 3 | **Four ways to run an ERP**. Cards: SaaS · Managed platform · IaaS / private cloud · On-premises | There are four models. With software as a service, the vendor hosts and runs the software, and the customer simply subscribes and uses a browser. With a managed cloud platform, the platform hosts it, but the client or partner can deploy custom code. With infrastructure as a service, the company rents virtual servers and installs the ERP itself. And on premises, the company runs its own servers, so its IT team handles hardware, backups, patches and upgrades. |
| 4 | Deployment models compared | Compare the trade offs. Software as a service has a low up front cost and needs minimal IT skills, but custom code is limited and upgrades come on the vendor's schedule. A managed platform allows custom code with moderate IT skills. On premises or self managed servers give full control, even over data location, and can work on a local network, but they need high IT skills and a large up front investment. More control always means more responsibility. |
| 5 | **One product, three models**. Cards: Odoo Online · Odoo.sh · On-premise | Odoo is a useful example because it offers all three models. Odoo Online is software as a service hosted by Odoo. Custom Python modules cannot be installed there, though Studio, an Enterprise feature, allows some no code changes. Odoo dot S H is a cloud platform for Odoo Enterprise that supports custom modules, with development, staging and production branches. And on premise, Community is open source while Enterprise needs a subscription. Plan conditions change, so always check the current offering before advising a client. |
| 6 | **Six selection criteria**. Cards: Customization · Connectivity · Regulation · IT capacity · Total cost of ownership · Upgrade policy | Decide using six criteria. Does the client need custom modules? Then pure software as a service may be ruled out. Is the internet reliable at every site? Do regulations require data to stay in a particular place? Who will patch, back up and monitor the server at night? Compare the total cost of ownership over three to five years, not just year one. And remember the upgrade policy: SaaS clients get upgrades on the vendor's schedule, while self hosted clients must plan and fund them. |
| 7 | Who is responsible? | Here is a common mistake: assuming the cloud vendor is responsible for everything. Hardware, the database and backups move to the vendor or platform as you move to the cloud. But look at the last two rows. Users, access rights and data quality are always the client's responsibility, no matter where the ERP runs. So if a SaaS client's salesperson can see every customer's invoices, it is the client and its partner who must fix it, not the vendor. |
| 8 | **Lumen chose SaaS, Harbor a managed platform**. Cards: Lumen Consulting Group → SaaS · Harbor Steelworks → managed platform | So what did our two clients choose? Lumen Consulting Group chose software as a service: staff need access from anywhere, requirements were standard, and there is no IT team. Harbor Steelworks needed a custom quality inspection module and worried about internet outages, so it chose a managed cloud platform for custom code, and invested in a backup internet line. On premises was rejected, because nobody was available to maintain a server. |
| 9 | **Key takeaways**. Cards: Several models · Control vs effort · Decide on criteria · Always the client's | To recap. The deployment options are software as a service, a managed cloud platform, and on premises or self managed cloud servers. SaaS minimises IT effort but limits custom code, while on premises maximises control but needs IT skills. Decide using customization needs, connectivity, regulation, IT capacity and three to five year total cost. Users, access and data quality always stay with the client, and always verify current vendor plans. Now open the lesson and try the exercises: walk the decision tree and match each model to its characteristic. |
