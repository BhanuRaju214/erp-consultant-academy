# Napkin AI prompts

Ready-to-paste prompts for Napkin AI diagrams that complement the in-portal visual blocks. They cover process, workflow, decision and lifecycle content, where a polished static diagram adds the most. Every prompt uses only facts, step names and Odoo labels taken from the lesson or process it belongs to. Fictional companies only (Northwind Office Supplies, Timbercraft, Urban Thread, etc.).

Cross-references: the `Napkin` column in `enhancement-matrix.md` points to these IDs. Section (c) of `image-requirements.md` lists them again with the in-portal block each diagram supports.

## Export-and-import workflow (manual, no API assumed)

1. Open **napkin.ai** and sign in with the licensee's account. Create a **new Napkin**.
2. Paste the **Prompt text** of one entry (only the text inside the code block).
3. Select the text and click the generate (spark) icon. From the proposed visuals, pick one that matches the **Style** given below (flowchart, timeline, decision tree, cycle, comparison or hub).
4. Edit the labels so every step, actor and Odoo label reads exactly as in the prompt. Remove any extra nodes or wording Napkin invented. Apply brand colours where possible: navy `#0b1120`, cyan `#17C0E2`.
5. **Verify correctness against the lesson** using the entry's **Review checklist**. Open the lesson in the portal side by side. A domain reviewer (functional consultant) signs off.
6. Export as **SVG**. If SVG is unavailable on the plan, export **PNG at 2x**.
7. Save to `public/visuals/<course-slug>/<lesson-slug>/<file>.svg` using the **File** name given. Business processes use `public/visuals/processes/<process-slug>/`, and configuration scenarios use `public/visuals/config-scenarios/<scenario-slug>/`.
8. Register the file in `src/content/visuals/registry.ts` (create the registry if it does not exist yet) with: `src`, `caption` (draft title), `alt` (draft alt text), `source: "Napkin AI"`, `width`/`height` (from the export), and the rights note *"Generated by the licensee's Napkin account — confirm plan terms for commercial use."*
9. Insert a `visual-figure` block into the lesson (or process/scenario markdown) near the section it illustrates:

   ````markdown
   ```visual-figure
   { "src": "/visuals/odoo-sales/overview-and-business-problems/quotation-to-invoice-flow.svg",
     "alt": "…", "caption": "…", "credit": "Diagram created with Napkin AI", "width": 1600, "height": 900 }
   ```
   ````
   (Escape the backticks inside TypeScript content files.)
10. Run `npm run visuals:check` and fix any unregistered or missing file before publishing.

**Rules.** Do not add facts that are not in the lesson. Keep "(verify…)" caveats out of the diagram text and keep them in the lesson body. The checklist names each one so the reviewer confirms the lesson still carries it. Keep the in-portal block as well: Napkin figures are static, so the interactive or accessible block stays the primary teaching element.

### NP-08 · Standard-first ladder
- **Source:** `erp-fundamentals/standard-vs-customization` · **File:** `standard-first-ladder.svg` · **Style:** decision tree
- **Draft title:** The standard-first ladder

```text
Before agreeing to any customization, walk down this ladder and stop at the first "yes".
1. Does standard already do it? Yes: use standard.
2. Can configuration achieve it (a setting, a pricelist rule, an automation)? Yes: configure.
3. Can the process change? Yes: change the process.
4. Is there a ready-made module from the vendor or a trusted source? Yes: evaluate quality and upgrade support, then use it.
5. Only then: custom development, with a written specification and cost/benefit justification.
```
- **Alt text:** Decision tree with five questions in order (standard, configuration, process change, ready-made module, custom development), each "yes" ending the search before customization is considered.
- **Review checklist:** order of the five rungs is exact; custom development is shown as the last resort, not one option among equals.

### NP-12 · Data migration cycle
- **Source:** `implementation-methodology/phase-5-data-migration` · **File:** `data-migration-cycle.svg` · **Style:** cycle
- **Draft title:** Data migration: six steps and trial-load loop

```text
1. Extract: export each source system in full; record date, source and row counts.
2. Cleanse (owned by the business): remove duplicates and inactive records, complete mandatory values, standardise formats.
3. Map and transform: map source to target fields and translate codes.

5. Load (trial): import with templates, or scripts via the API for large migrations.

```
- **Alt text:** Cycle diagram of extract, cleanse, map, validate, load and reconcile, with a loop that repeats trial loads two to three times before the final migration load.
